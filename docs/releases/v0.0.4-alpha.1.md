# Scarp v0.0.4-alpha.1 — Finite Floating-Point Scalars

Release candidate prepared 2026-10-30. **Not published or tagged.** Exact
maintainer authorization and successful final-main checks/packages are required
before publication. The latest published prerelease remains v0.0.3-beta.3;
its tags and assets are unchanged. This is experimental alpha software, with
syntax and Rust API compatibility subject to change.

## Included

- Finite IEEE-754 binary64 `float` scalars, decimal/scientific literals,
  inferred immutable/mutable bindings, assignment, negation, arithmetic,
  comparisons and numeric equality. Plain integer literals remain signed i64.
- Typed float parameters, results and defaults in existing `funcra` declarations,
  positional/named calls, recursion, purity and `needs`/`ensures` contracts.
- A private checked `FiniteFloat` Rust wrapper rejects NaN and either infinity.
  Arithmetic overflow is diagnosed before storing a nonfinite result.
- Both signed zeros are observable in output and host bits, compare equal, and
  are rejected as divisors with E0008. Subnormal results and underflow to signed
  zero are allowed. Binary arithmetic rounds; decimal fractions are not exact.
- Locale-independent shortest round-trip output with a float marker: `1.0`,
  `-0.0`, and scientific notation where appropriate. Fixed/scientific selection
  follows Rust's float formatter and is not a separate cross-version guarantee.
- E0030 for malformed or nonfinite literals, E0031 for nonfinite arithmetic.
  Existing E0001–E0029 assignments and source-linked call traces are preserved.
- All six budgets, heap call frames, silent `check`, stored output snapshots,
  and atomic validation of stdout/stderr remain in force. Source, evaluation,
  contract and budget failures replay no program output. Sink I/O can fail after
  earlier bytes; logical budgets do not bound all process memory or parsing.
- Twenty exact-output examples, including Newton root refinement and exponential
  smoothing. Native smoke tests exercise floats, streams and deliberate failures.

```scarp
pure funcra blend(value: float, target: float, weight: float = 0.25) -> float
    needs weight >= 0.0 && weight <= 1.0;
{
    return value + (target - value) * weight;
}
print(blend(10.0, 20.0), blend(weight: 0.5, target: 20.0, value: 10.0));
```

Exact stdout: `12.5 15.0` followed by LF. See [floats](../floats.md),
[functions](../functions.md), [budgets](../budgets.md), and the
[implementation audit](../development/finite-floats-audit.md).

## Compatibility from beta.3

Existing integer, string, boolean, binding, output, function and CLI behavior is
preserved. Numeric operands must share a type: `1 + 0.5` is a type error; use
`1.0 + 0.5`. Bindings infer one fixed type. There are no casts or new local
type-annotation syntax. `float` is a contextual type name, not a reserved binding
word. `1.`, `.5`, `1e`, and `1.2.3` are rejected with E0030; `1e309` is a valid
token whose magnitude is rejected during parsing. `tokens` remains lexical.

Rust hosts must handle new Float variants in public token/AST/value/type enums
and the two new diagnostics in exhaustive matches. `Value::as_float()` returns
an optional finite f64 copy; `FiniteFloat::new()` is the checked constructor.
Legacy integer expression entry points keep their i64 result. See
[compatibility](../compatibility.md) and [embedding](../embedding.md).

## Candidate packages and commands

The native package workflow targets Windows x64 MSVC, Linux x64 GNU on Ubuntu
22.04, and Apple Silicon macOS on macOS 15. No Intel macOS, Windows ARM64,
installer or registry package is included. Source builds require Rust 1.74 or
later; running an extracted binary does not require Rust. Zero third-party
Rust dependencies, unsafe-forbid policy, and `publish = false` remain unchanged.

Expected archive names use `scarp-0.0.4-alpha.1-` followed by
`x86_64-pc-windows-msvc.zip`, `x86_64-unknown-linux-gnu.tar.gz`, or
`aarch64-apple-darwin.tar.gz`. Each has a companion `.sha256`; `SHA256SUMS`
combines all three. These seven files are candidate artifacts until publication.
Archives include the executable, license, guides, all examples/fixtures and a
clean `BUILD-INFO.txt` with exact commit, compiler and native target. Checksums
detect corruption; archives are not promised byte-identical across build hosts.

```sh
./scarp --version
./scarp run examples/float_refinement.srp
./scarp run examples/float_smoothing.srp
./scarp check --max-calls 1000 examples/float_refinement.srp
```

Expected version: `scarp 0.0.4-alpha.1`. Use `./scarp.exe` on Windows. Existing
`run`, `check` and `tokens` spellings are preserved; no CLI rename is included.

## Validation and remaining scope

The [feature audit](../development/finite-floats-audit.md) records the accepted
feature's exact-main source/package runs and local regression evidence. The
release preparation must separately pass fmt, Clippy, debug/release tests, build,
rustdoc, both check scripts, release-tool tests, Rust 1.74 and stable native CI.
Verify all three downloaded archives against that final source's Git blobs,
build records, permissions and SHA-256 before considering an alpha release.
See [release preparation](../releasing.md) for the authorization and asset gates.

Vectors, tensors, automatic differentiation, GPUs, casts, numerical built-ins,
bit operations, native compilation, CLI redesign, imports, package management,
custom types and self-hosting are excluded. No native performance-parity claim
is made. Numerical vectors are the recommended next separate milestone after
successful scalar integration and explicit scope review.
