# Scarp v0.0.3-beta.3 — Typed Functions

Experimental prerelease, 2026-10-29. This publishes the typed `funcra` function
system integrated into main after beta.2, with CLI resource controls, updated
guides, and stronger native-package verification. Syntax and Rust APIs remain
experimental. The temporary `0.0.4-dev` integration identifier was never a public
release; beta.3 is the next requested sequential public beta. Existing tags and
assets remain unchanged.

## Included

- Typed file-level `funcra` declarations with integer, string, boolean, and unit
  results, explicit returns, lexical isolation, and immutable parameters.
- Forward calls, recursion and mutual recursion, positional/named/default
  arguments, source-order argument evaluation, and static return-path checking.
- Verified `pure funcra` declarations and executable boolean `needs` / `ensures`
  contracts. Postconditions inspect `result`. These are runtime checks, not proofs.
- Heap-managed call frames, bounded source call traces, immutable signature and
  call-graph metadata, and function calls in saved repeat counts.
- CLI `--max-call-depth`, `--max-calls`, `--max-live-slots`, and
  `--max-capture-bytes`, alongside existing work/output limits. Both `run` and
  `check` enforce all six, including snapshot caps for programs without calls.
- Resource failures identify the exhausted budget, configured cap, and CLI/API
  control. Source, type, arithmetic, contract, and budget failures discard
  pending stdout and stderr. Sink failures may leave earlier bytes.
- Native archives test all 18 exact-output examples, separate streams, deliberate
  failures, and CLI resource boundaries. Verification compares bundled root
  documentation, all guides, and all examples with exact release Git blobs.

```scarp
pure funcra scale(value: integer, factor: integer = 2) -> integer
    needs factor > 0;
    ensures result == value * factor;
{
    return value * factor;
}

print(scale(6), scale(factor: 3, value: 7));
```

## Run after extraction

The [prerelease page](https://github.com/sanskarIN/scarp-lang/releases/tag/v0.0.3-beta.3)
provides three native archives, their `.sha256` files, and `SHA256SUMS`:

| Archive suffix | Native platform |
| --- | --- |
| `x86_64-pc-windows-msvc.zip` | Windows x64 MSVC |
| `x86_64-unknown-linux-gnu.tar.gz` | Linux x64 GNU, built on Ubuntu 22.04 |
| `aarch64-apple-darwin.tar.gz` | Apple Silicon macOS |

Verify the matching checksum before extracting. Archives include the executable,
license, guides, examples/expected output, and `BUILD-INFO.txt` with the full
version, exact source SHA, compiler, native target, and clean working-tree state.
No installer, registry package, Intel macOS, or Windows ARM64 binary is provided.
Checksums detect corruption; they are not signatures.

```sh
./scarp --version
./scarp run examples/functions.srp
./scarp run examples/function_contracts.srp
./scarp run --max-call-depth 512 examples/function_recursion.srp
./scarp check --max-capture-bytes 1048576 examples/functions.srp
```

Use `./scarp.exe` on Windows. Expected version: `scarp 0.0.3-beta.3`.
Rust 1.74 or later is required only for source builds; there are no third-party
Rust dependencies and `publish = false` remains set.

## Compatibility from beta.2

Existing bind/var, output, loop, and arithmetic semantics and command spellings
are preserved. `println` remains an exact alias. `run`, `check`, and `tokens`
remain the commands; `compile`, `exec`, `verify`, and `inspect` are unsupported.

Function words `funcra`, `pure`, `return`, `needs`, and `ensures` become reserved
binding names. Unknown call names now report E0023. E0001–E0019 keep their
assignments; E0020–E0029 add function/contract/resource diagnostics. Rust hosts
with exhaustive public enum matches must handle the new function, call, return,
token, and unit variants. See [compatibility](../compatibility.md).

Existing entry-point signatures and two-field `ExecutionLimits` literals remain
valid. Old entry points use additional default caps: 256 active user frames,
100,000 cumulative calls, 1,000,000 live slots, and 16 MiB logical output snapshot
storage. Programs without functions also use slot/snapshot caps. Hosts needing
different limits can use additive `ExecutionOptions` APIs; CLI users can set
all six budgets. Logical execution limits do not bound all parser allocations
or total process memory.

## Scope and validation

This release adapts only the function core from the older experimental stack.
Decimals, vectors, bit operations, numerical built-ins, C/native compilation,
and the redesigned CLI remain separate. There are no closures, first-class or
nested functions, imports, custom types, standard library, package manager, or
self-hosting. Function execution is interpreted; native performance parity has
not been established.

Publication requires successful exact-final-main Rust checks on Windows, Linux,
macOS and Rust 1.74, plus all three native package jobs. A separate publisher
checks those seven jobs, archive hashes/source records, every packaged source
file, and draft downloads before publishing an annotated tag and prerelease.
All seven public asset URLs are then downloaded without credentials and checked.
See [release preparation](../releasing.md) for the process and
[the validation record](v0.0.3-beta.3-validation.md) for baseline/local evidence.
