# Scarp v0.0.5-alpha.1 — source modules candidate

Status: unpublished experimental development candidate. No tag, release request
or draft authorizes publication. The latest published prerelease remains
[v0.0.4-alpha.4](https://github.com/sanskarIN/scarp-lang/releases/tag/v0.0.4-alpha.4).

The next version is **0.0.5-alpha.1** rather than 0.0.4-alpha.5 because this
milestone adds language-level program organization and explicit public source
loading APIs after the 0.0.4 numerical series. It remains experimental; this is
not a stability or production-readiness claim.

## Implemented

- Relative `.srp` imports with explicit aliases and qualified public functions
  and immutable scalar literal constants. Private helpers, typed symbols,
  named/default arguments, purity, needs/ensures and local mutual references
  integrate with the existing resolver and immutable runtime.
- Separate bounded graph discovery, linking, checking and execution APIs.
  Filesystem and in-memory loaders keep I/O out of the lexer/parser. Compiled
  module programs own their sources and support independent concurrent execution.
- Canonical source deduplication, cycle detection, relative path/root checks,
  bounded reads and independent file/depth/source/import/expansion limits.
- Source-aware E0037–E0043 diagnostics, cross-file parameter locations and runtime
  traces. Existing diagnostic codes, single-file semantic errors, seven CLI
  resource flags, numerical behavior and atomic output are preserved.
- A three-file numerical example, exact diagnostic fixtures, public API/CLI
  regressions and a beginner import tutorial. Introductory docs now distinguish
  published alpha.4 from this development candidate.

```sh
cargo run --locked --offline -- run examples/module_demo.srp
cargo run --locked --offline -- check examples/module_demo.srp
```

## Compatibility and limits

Ordinary single-file source remains supported. `import`, `pub` and `as` are
contextual identifiers. Public Rust syntax enums gain import/export and dot
variants; exhaustive matches need updating. Existing source-string APIs do not
perform implicit I/O and direct module declarations to the new explicit APIs.
Public `Span` and `Diagnostic` layouts remain intact; module errors add an owned
source-map wrapper.

Libraries are declaration-only. Exported values are scalar literals, not runtime
globals, vectors or tiles. Imports cannot be re-exported. Cyclic module graphs,
packages, network loading, user-defined structures, native compilation and LSP
are deferred. Source limits are logical caps, not a process-memory guarantee.
The filesystem loader assumes a trusted tree and is not a race-proof sandbox
against concurrent hostile filesystem mutation. See [modules](../modules.md).

Rust 2021, minimum Rust 1.74, no external Rust dependencies, Apache-2.0,
`publish = false` and `unsafe_code = "forbid"` remain unchanged.

## Candidate verification and publication

The required gates remain formatting, strict Clippy, debug/release tests, build,
warnings-as-errors Rustdoc, check scripts, examples, documentation checks, both
benchmark smoke suites, four hosted Rust jobs and three native package jobs.
Candidate evidence must name its exact source SHA and actual completed runs.
Packages retain Windows x64 MSVC, Linux x64 GNU and macOS ARM64, checksums,
extraction smoke tests and exact-source verification. Required package contents
now include the module guide, tutorial, specification and nested library files,
in addition to the inherited alpha.4 files.

Before publication, obtain fresh maintainer approval for this exact version and
fully verified source SHA. Only then may a reviewed release request enable the
existing guarded publisher. Previous alpha.4 approval does not authorize this
candidate. Published tags/assets and historical release notes remain unchanged.
No website or GitHub Pages deployment is included.
