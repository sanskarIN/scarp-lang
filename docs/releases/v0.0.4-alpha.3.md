# Scarp v0.0.4-alpha.3 — Numerical Functions and Bounded Memory Control

Experimental prerelease candidate. The GitHub release page must be checked for
actual publication status, exact commit and verified downloads:
https://github.com/sanskarIN/scarp-lang/releases/tag/v0.0.4-alpha.3

## Included in the source and expected native packages

- New pure numerical functions `norm(vector) -> float` and
  `normalize(vector) -> vector`. The scaled L2 implementation avoids
  unnecessary intermediate square overflow/underflow, while rejecting a
  nonrepresentable final scalar norm. Normalizing empty or all-zero vectors
  gives E0034; `norm([])` yields +0.0.
- Terminal self-transfer in `funcra`: a direct
  `return same_function(arguments);` can replace the current function frame
  when that function has no `ensures` postconditions. Each logical call
  still counts toward the total-call and execution-step budgets, and
  preconditions/defaults run every invocation. Nonterminal calls and
  functions with postconditions retain ordinary frames. Selected errors
  retain bounded call traces; both output streams remain atomic on errors.
- New independent `--max-vector-bytes` for `scarp run` and `scarp check`,
  plus `ExecutionOptions.max_vector_bytes` and the Rust host helper
  `numeric::evaluate_with_vector_limit`. Default quota: **8,388,608
  cumulative newly reserved numeric payload bytes**. It applies to new
  vector literals, fill/add/scale/clamp/softmax and **normalize** buffers.
  It does not double-count immutable references; prior allocations do not
  get refunded when a value leaves scope. E0036 reports quota exhaustion.
- The earlier ten alpha.2 numerical kernels, finite float/vector types,
  typed `funcra` contracts, iteration and other execution limits remain.
- Three new runnable exact-output examples: `scaled_norm`,
  `terminal_recursion`, and `vector_allocation`.
- Branch lifecycle housekeeping: maintain `main`, `development`, temporary
  `release/*` integration branches and focused feature PRs, and prune only
  inactive `scarp/*` heads fully contained in main after live ancestry
  and open-PR protection checks.

## Example

```scarp
bind v = [3.0, 4.0];
print(norm(v));
print(normalize(v));
```

Output:

```text
5.0
[0.6, 0.8]
```

For a separate quota example:

```sh
scarp run --max-vector-bytes 24 examples/vector_allocation.srp
scarp check --max-vector-bytes 24 examples/vector_allocation.srp
scarp run --max-call-depth 1 examples/terminal_recursion.srp
```

## Delivery and security gates

This release may publish only from an exact `main` source commit after
successful Rust source, formatting, Clippy, tests and documentation checks
on Linux/macOS/Windows plus minimum Rust 1.74, along with all three native
package jobs on the identical source SHA. Candidate archive contents and
SHA-256 digests are validated against source blobs before a draft is
published; public download digests are verified again before completion.
An unsuccessful or incomplete gate is **not** a published release.

Targets: Windows x64 MSVC, Linux x64 GNU and Apple Silicon macOS. Source
builds require Rust 1.74+, with Apache-2.0 licensing and no new external
Rust dependencies, general GC/ownership/pointer syntax or unsafe Rust.

## API changes and limitations

The public Rust `ExecutionOptions` struct gains a required
`max_vector_bytes` field for hosts constructing exhaustive literals.
Using `ExecutionOptions::default()` or struct update
`..ExecutionOptions::default()` requires no additional edit, and the
two-field `ExecutionLimits` remains unchanged. Rust enum additions and
resource counts remain experimental and are not guaranteed stable.

The new quota counts cumulative *finite-vector element payload allocated
through the interpreter*, not live heap, total process RAM, host-supplied
vectors, parser allocations, `Vec`/`Arc` overhead, strings, thread
stacks or OS buffers. It is not a sandbox or a custom low-level memory
management system. Execution remains interpreted: there is no LSP, package
manager, autograd, GPU backend, native codegen or general tensor engine in
this prerelease. Other independent experimental draft PRs remain unmerged.
