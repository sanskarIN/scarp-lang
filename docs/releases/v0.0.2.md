# Scarp v0.0.2 development notes

**Draft. Unreleased and untagged.** This document prepares the next milestone;
it does not authorize merging, tagging, or publishing. The latest published
release remains v0.0.1. Development builds identify themselves as `0.0.2-dev`.

## Implemented on feature branches

- Immutable integer bindings: `let name = expression;`.
- Explicit mutable bindings: `let mut name = expression;`.
- Assignment and checked `+=`, `-=`, `*=`, `/=` statements.
- Lexical block scopes, shadowing, and nearest-binding assignment.
- Name resolution before evaluation, with unknown/duplicate/reserved-name errors.
- Immutable-assignment diagnostics with the declaration's source location.
- Independent 64-level limits for blocks and expression grouping.
- Fresh storage on every execution and captured print values that survive later mutation.
- `scarp check` for silent validation of names and arithmetic.
- Efficient sequential token locations and expanded conformance testing.
- A separate optional draft adds string-valued variables, primitive type checks,
  fixed assignment types, and immutable string snapshots.
- A dependent boolean extension adds literals, comparisons, fixed boolean
  binding types, and readable short-circuit `and`, `or`, and `not` operators.
- A further dependent feature adds boolean `if`/`elif`/`else` decisions, lexical
  body scopes, and a flat execution plan with forward jumps.
- A performance branch reuses evaluator work buffers, discards validation print
  values immediately, and adds reproducible benchmarks for separate stages.

```scarp
let mut total = 1;
{
    let total = total + 10;
    println(total); // 11
}
total += 2;
println(total); // 3
```

The complete language and variable references describe exact behavior. User
functions, modules, and native compilation are not implemented. The
string-value extension remains a separate dependent draft for review; it adds
primitive checks, not a general type system or string arithmetic.

## Library migration from v0.0.1

The loop extension adds while/break/continue and default deterministic execution
and print budgets. CLI options and `ExecutionLimits` embedding APIs override the
defaults. Budget failures preserve atomic program output. See
[the loop design](../proposals/0006-bounded-loops.md).

`parse(source)` returns unresolved syntax. `compile(source)` now resolves names
and returns an immutable `ResolvedProgram`; use its metadata methods instead of
editing execution storage. `resolver::resolve` consumes an existing syntax tree.
`execute` accepts the resolved program. `check` and `interpreter::validate`
perform arithmetic validation without an output sink. `run` retains the source
plus writer interface. Syntax and library APIs remain experimental.

The string extension generalizes `PrintArgument::Integer` to
`PrintArgument::Expression`, adds `Value`/`ValueType`, and exposes inferred slot
types through `binding_types`. `evaluator::evaluate` keeps its integer result;
`evaluate_value` supports either primitive kind.

## Validation and review

The branch stack contains separate PRs for immutable bindings, mutability,
scopes, validation/development tooling, and optional string values. Review in
that order. Debug/release
tests include long declaration and assignment chains, 20,000 sibling blocks,
combined nesting boundaries, concurrent execution, generated scoped programs,
and malformed source/token mutations. CI checks three operating systems and
Rust 1.74.0. Native package jobs smoke-test extracted development archives.

Those CI archives are development artifacts, not published prerelease assets.
No v0.0.2 release tag, draft GitHub Release, or registry publication is created by
this work. Branches must remain outside main until the maintainer explicitly
requests integration.

## Before a future prerelease

After explicit authorization, review and integrate the PR stack, set the final
package version, rerun checks and package builds on the resulting main commit,
and verify source records and checksums. Tagging and publication each require
the maintainer's instruction. Do not reuse the existing v0.0.1 tag or assets.
