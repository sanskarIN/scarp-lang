# Scarp v0.0.4-alpha.4 — numerical and runtime candidate

Status: unpublished experimental prerelease candidate, prepared 1 November 2026.
The source version is not publication evidence. No alpha.4 tag or release request
has been created. Exact version/source approval follows all verification gates.

## Numerical additions

- Immutable `tile` values with explicit row/column counts, row-major visible
  cells, shape-aware equality, stable display and typed `funcra` signatures.
- `tile`, `height`, `width`, `cell`, `lane`, `unroll` and `turn`, adapted from
  PR #53 onto current vector windows and cumulative allocation accounting.
- `matvec`, `matmul`, `tileadd` and `tilescale` for bounded linear algebra.
  All dimensions, output sizes and work estimates use checked arithmetic.
- The post-alpha.3 main additions: shared `window`, materializing `stitch`,
  `logsumexp`, `logsoftmax`, stable score selection, `crossentropy`, `logprob`,
  `lossgrad` and `onehot`. Existing vector kernels retain their behavior.
- Seven tested executable demonstrations cover inference, linear composition,
  score decoding, softmax/loss, one-hot targets, forward computation and windows.

Tiles have at most 65,536 finite binary64 cells, and each axis is in `0..=65536`.
Empty axes remain part of value identity. `(m,0)*(0,n)` returns `m*n` positive
zeros under ordinary size/work/allocation caps. Matrix products use ordered
Neumaier compensation compatible with `dot`. Products, sums, compensation and
final cells must remain finite; cancellation cannot excuse intermediate overflow.
Subnormals and signed-zero storage follow existing scalar rules. There is no
broadcasting, implicit numeric conversion or mutable cell access.

## Runtime and correctness

Compiler-planned scope retirement from PR #51 drops inaccessible values at block
exits and loop transfers. Function completion retires locals while retaining
parameters/results for postconditions. Defaults, recursion, terminal frame
replacement and output snapshots preserve immutable values. The test-only
must-initialization audit checks reachable plans, default/result dependencies,
slot indices, jumps and prematurely retired postcondition parameters; it is not
a proof covering all possible future language features.

Eligible terminal self-calls reuse slot, supplied-parameter and expression
buffers after outgoing argument evaluation. They retain existing initialization
work charges, defaults, needs checks, call limits and bounded source traces.
The measurement procedure and observations are recorded in
[the performance guide](../performance.md); no cross-language speed claim is made.

Fresh buffers prepay cumulative numerical payload and native work before
reservation/loops. Matrix multiplication charges its full inner-product work
even for a one-cell result. Tile construction/unroll share visible storage;
lane/transpose/arithmetic allocate fresh charged payload. Zero-output kernels
skip empty nested loops. Selected tile output charges row delimiters as well as
cells, including zero-width shapes.

New fixtures verify dimension and cell spans, shape explanations and nested
`funcra` context. Existing E0015/E0017/E0024/E0029/E0030–E0036 meanings are
preserved; no new diagnostic codes were required. Both program streams remain
empty after semantic or budget failures.

## Compatibility and limits

Existing source syntax, CLI command/option names, exit codes and Rust execution
entry points remain valid. Public Rust enums gain `Tile` and matrix built-in
variants, requiring updates to exhaustive matches. The package remains
dependency-free, Apache-2.0, edition 2021, Rust 1.74 minimum, `publish = false`,
and `unsafe_code = "forbid"`.

The allocation ledger counts cumulative new element payload, not peak live
storage, parser/frame/container overhead or process RSS. A visible window/tile
can retain its entire backing allocation. Snapshot storage is a separate logical
quantity. This remains an interpreter for small numerical programs, without a
production BLAS, tensor framework, modules, autograd, GPU or native-code backend.

## Build, packages and release gates

```sh
cargo build --locked --offline --release
cargo run --locked --offline -- run examples/matrix_forward.srp
cargo test --locked --offline
```

Native archive targets remain Windows x64 MSVC, Linux x64 GNU and macOS ARM64.
Use `scripts/package.ps1` on each matching native toolchain; it builds, extracts
and tests the executable and every expected-output example. Archives include
guides, examples and an exact-source clean build record. Three archives, three
sidecar SHA-256 files and one `SHA256SUMS` manifest are required.

The final validation record must contain formatting, Clippy, debug/release tests,
build, Rustdoc, Windows/Unix validation, both benchmark smoke suites, four hosted
Rust jobs, three native package jobs and source/archive checksum verification
for the exact approved source. Current evidence and remaining gates are tracked
in the integration PR and engineering report; older draft-PR runs are insufficient.

The completed alpha.3 request is removed. A new reviewed request must contain
the explicitly approved full `source_commit` SHA. The existing publisher checks
both that source's exact-main CI/packages and the current control revision,
creates a new annotated tag only after gates, verifies a draft, publishes with
`prerelease=true`/`make_latest=false`, then checks all public downloads. Until
approval, there is no release request, tag, draft release or publication.
